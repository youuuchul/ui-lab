# 유저 스토리·인수 조건
요구를 사용자 관점의 한 문장과 확인 가능한 조건으로 나눈다.

## 형식
```text
<사용자>로서, <목적>을 위해 <행동>하고 싶다.

인수 조건
- Given <상황> When <행동> Then <결과>
```

## 좋은 스토리의 기준
- 사용자 가치가 보인다. "API 연동" 같은 작업 단위는 스토리가 아니라 하위 작업이다.
- 한 스프린트 안에 끝난다. 크면 나눈다(단계 분리 참고).
- 인수 조건으로 완료를 판단할 수 있다. "잘 동작한다"는 조건이 아니다.

## 예시
```text
알림을 줄이고 싶은 사용자로서, 필요한 알림은 계속 받기 위해
푸시를 끄지 않고 종류별로 끄고 싶다.

- Given 푸시 켬, When 야간 알림을 끈다, Then 댓글·답글 알림은 계속 받는다.
- Given 푸시 끔, When 설정 화면을 연다, Then 하위 설정이 모두 꺼진 모양으로 보인다.
```

```text
처음 대화를 시작하는 사용자로서, 첫마디를 고민하지 않기 위해
추천 답변을 골라 고쳐 보내고 싶다.

- Given 입력창이 비어 있음, When 8초가 지난다, Then 추천 버튼이 강조된다.
- Given 추천 패널 열림, When 추천 하나를 누른다, Then 입력창에 채워지고 바로 보내지지 않는다.
```
두 번째 예시는 [채팅 입력창](#/components/chat-input)의 실제 동작이다.
