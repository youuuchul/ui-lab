# 기능 명세서
화면·상태·동작·예외를 개발과 QA가 그대로 구현·검증할 수 있게 적는다.

## 언제 쓰나
- PRD에서 범위가 정해진 뒤, 개발 착수 전
- 상태가 여러 개이거나 다른 설정과 연동되는 기능

## 쓰는 법
- 화면이 아니라 **상태**를 기준으로 적는다. 상태 표가 문서의 중심이다.
- 예외(빈 값, 실패, 권한 없음, 느린 네트워크)를 정상 흐름과 같은 무게로 적는다.
- 인수 조건은 Given-When-Then으로, QA가 그대로 테스트 케이스로 쓸 수 있게.

## 템플릿
```markdown
# <기능 이름> 기능 명세
관련 PRD · 디자인 · 상태(초안/확정)

## 목적
- 한 문장

## 사용자 시나리오
1. 누가 어떤 상황에서
2. 무엇을 하고
3. 어떤 결과를 얻는다

## 상태
| 상태 | 화면 | 들어오는 조건 | 나가는 조건 |

## 동작
- 입력별 반응 (클릭, 키보드, 터치)

## 예외
- 빈 값 / 실패 / 권한 / 느린 응답 / 중복 입력

## 인수 조건
- Given ~ When ~ Then ~

## 측정
- 이벤트 이름과 속성

## 범위 밖
- 이번에 하지 않는 것
```

## 예시: 알림 설정 (토글)
### 상태
| 상태         | 푸시 | 하위 표시 | 하위 저장값 |
|--------------|------|-----------|-------------|
| 기본         | 켬   | 저장값    | 유지        |
| 푸시 끔      | 끔   | 모두 끔   | 유지        |
| 푸시 다시 켬 | 켬   | 저장값    | 유지        |

### 동작
- 푸시를 끄면 하위는 꺼진 모양으로 보이고, 사용자가 고른 하위 값은 저장해 둔다.
- 푸시가 꺼진 채 하위 하나를 켜면 푸시와 그 항목만 켠다. 다른 하위는 켜지 않는다.

### 예외
- 저장 실패: 토글을 이전 상태로 되돌리고 토스트로 알린다.
- 기기 알림 권한 없음: 푸시를 켜는 순간 권한 요청. 거부하면 꺼진 상태로 두고 설정 바로가기를 보여준다.

### 인수 조건
- Given 푸시 켬·야간 알림 켬, When 푸시를 끈다, Then 야간 알림이 꺼진 모양으로 보인다.
- Given 위 상태, When 푸시를 다시 켠다, Then 야간 알림이 켜진 모양으로 돌아온다.
- Given 푸시 끔, When 댓글·답글을 켠다, Then 푸시와 댓글·답글만 켜지고 야간 알림은 꺼져 있다.

### 측정
- `notification_setting_changed` { key, value, source: "parent" | "child" }
