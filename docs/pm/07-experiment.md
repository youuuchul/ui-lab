# 실험 설계서
바꾼 것이 지표를 움직였는지 판단할 기준을 실험 전에 정한다.

## 템플릿
```markdown
# <실험 이름>
## 가설
<변경>을 하면 <사용자 행동>이 바뀌어 <지표>가 <방향>으로 움직인다. 이유: <근거>

## 지표
- 핵심 지표(1개): 정의와 계산식
- 보조 지표: 
- 가드레일: 나빠지면 중단

## 설계
- 대상과 비율: 
- 기간: 요일 효과를 피하려 최소 1~2주
- 필요한 표본: 기준값·최소 감지 효과로 계산

## 판단 기준 (실험 전에 확정)
- 채택: 
- 기각: 
- 판단 보류: 

## 결과
- 수치, 신뢰구간, 해석, 다음 행동
```

## 예시 (가정)
- 가설: 하위 설정이 있으면 알림이 부담스러운 사용자가 푸시 전체 대신 일부만 끈다. 그래서 푸시 전체 끄기 비율이 줄어든다.
- 핵심 지표: 설정 화면 진입 사용자 중 푸시를 끈 비율
- 가드레일: 알림 클릭률이 기준 대비 유의하게 떨어지면 중단
- 판단 기준: 핵심 지표가 줄고 가드레일이 유지되면 전체 적용

## 자주 하는 실수
- 결과를 보고 지표를 고른다 → 판단 기준을 먼저 적는다.
- 중간에 유의해 보이면 멈춘다 → 정한 기간을 채운다.
- 평균만 본다 → 신규·기존, 플랫폼별로 나눠 본다.
