# 의사결정 기록
나중에 "왜 이렇게 했지?"에 답할 수 있게 결정과 버린 대안을 남긴다.

## 템플릿
```markdown
# <결정 제목>
날짜 · 결정한 사람 · 상태(제안/결정/폐기)

## 배경
## 선택지
1. A — 장점 / 단점
2. B — 장점 / 단점
## 결정
## 이유
## 영향과 되돌리는 조건
```

## 예시: 상위가 꺼졌을 때 하위를 어떻게 보일까
- 선택지
  1. 하위를 켜진 모양 그대로 잠근다 — 구현이 쉽다 / 켜져 있다고 읽힌다
  2. 하위를 꺼진 모양으로 보이고 값은 기억한다 — 상태가 정확하다 / 저장값과 표시값을 따로 관리해야 한다
- 결정: 2
- 이유: 상태를 잘못 읽게 하는 화면은 사용성 문제다. 저장값 분리는 한 번 만들면 끝난다.
- 같이 정한 것: 상위가 꺼진 채 하위를 켜면 그 항목과 상위만 켠다. 예전에 켜 둔 다른 하위는 되살리지 않는다.

이 저장소의 [토글](#/components/toggle) 동작이 이 결정을 따른다.
