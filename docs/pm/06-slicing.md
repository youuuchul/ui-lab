# 단계 분리·스프린트
큰 과제를 출시 가능한 작은 단위로 자르고, 스프린트에 담는다.

## 자르는 기준
- 세로로 자른다: 화면·서버·데이터를 조금씩 모두 포함해 사용자가 쓸 수 있는 단위.
- 가로로 자르지 않는다: "API만 먼저", "화면만 먼저"는 출시할 수 없다.
- 각 단계는 따로 출시해도 의미가 있어야 한다.

## 예시: 알림 설정 개편
| 단계 | 범위                             | 확인할 것             |
|------|----------------------------------|-----------------------|
| MVP  | 푸시 + 하위 2개, 상하위 연동     | 푸시 끄기 비율 변화   |
| v1   | 하위 종류 확대, 저장 실패 처리   | 문의 수, 설정 변경 수 |
| v2   | 시간대 지정(야간 시간 직접 설정) | 야간 알림 사용률      |

적용 사례마다 원본에서 "뺀 것"을 적어 둔 것도 같은 판단이다. 예를 들어 [캐릭터 대화 화면](#/blocks/chat-scene)은 스트리밍·호감도·라운드 결과를 빼고 대화 루프만 남겼다.

## 스프린트 계획
```markdown
## 스프린트 <번호> (기간)
목표: 한 문장 (예: 푸시 하위 설정을 10% 사용자에게 연다)

| 스토리 | 담당 | 추정 | 상태 |

위험: 일정에 영향을 줄 수 있는 것
완료 정의: 인수 조건 통과, QA 체크리스트 통과, 이벤트 로그 확인
```
