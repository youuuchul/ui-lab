# UI 검수 기준
항목을 추가하거나 고칠 때 확인하는 기준. 사용성이 먼저고, 다크패턴은 쓰지 않는다.

## 1. 상태와 방향
- 켜짐·선택·체크는 항상 "받는다·허용한다·보인다" 쪽이다. "방해 금지", "알림 끄기"처럼 켜면 막히는 라벨을 쓰지 않는다.
- 한 묶음 안의 컨트롤은 같은 방향으로 읽힌다. 하나만 반대 의미면 바꾼다.
- 현재 상태가 위치·색·글자 중 두 가지 이상으로 보인다. 색만으로 구분하지 않는다.

## 2. 연동
- 딸린 설정은 들여쓰기·선으로 묶어 상하위가 보이게 한다.
- 상위를 끄면 하위는 꺼진 모양으로 보인다. 켜진 모양 그대로 잠그지 않는다.
- 상위가 꺼진 채 하위를 켜면 상위도 켠다. 잠가 두고 이유를 설명하는 방식보다 우선한다.
- 자동으로 바뀌는 값은 사용자가 고른 범위를 넘지 않는다. 고르지 않은 항목을 같이 켜지 않는다.

## 3. 다크패턴 금지
- 기본값을 사용자에게 불리한 쪽(마케팅 수신 등)으로 켜 두지 않는다.
- 취소·해제·닫기를 숨기거나 흐리게 만들지 않는다. 확인과 같은 크기로 찾을 수 있게 한다.
- 시간 압박(타이머)은 실제로 시간이 행동을 막는 곳에만 쓴다.
- 되돌릴 수 없는 동작(삭제·제출)은 위험 색과 확인 단계를 둔다.

## 4. 데모
- 데모는 그 컴포넌트가 존재하는 이유가 되는 상태를 보여준다. 로딩 표시는 로딩 중인 모습이, 오류 표시는 오류가 보여야 한다.
- 한 번 지나가면 끝나는 상태는 반복하거나 다시 재생으로 다시 볼 수 있다.
- 데모의 문구·데이터는 실제 서비스에 있을 법한 값으로 쓴다. 장식용 가짜 일러스트를 넣지 않는다.

## 5. 접근성
- 역할과 상태: `role`, `aria-checked`, `aria-expanded`, `aria-selected`, `aria-busy`를 실제 상태와 맞춘다.
- 키보드만으로 모든 동작이 가능하고, 포커스 링이 보인다.
- 글자 없는 버튼은 `aria-label`이 있다.
- `prefers-reduced-motion`에서 이동·회전을 줄인다.

## 6. 디테일
인터페이스 디테일 원칙(make-interfaces-feel-better) 중 이 프로젝트에 맞춘 것.

- 겹친 둥근 요소는 바깥 반지름 = 안쪽 반지름 + 안쪽 여백.
- 누르는 요소는 40×40px 이상. 작으면 투명한 영역을 넓힌다. 이웃과 겹치지 않는다.
- 눌림 축소는 `scale(0.96)`. 0.95보다 작게 줄이지 않는다.
- 바뀌는 숫자(타이머, 개수)는 `tabular-nums`.
- `transition: all`(`transition-all`)을 쓰지 않는다. 바뀌는 속성만 적는다.
- `will-change`는 transform·opacity·filter에만, 끊김이 보일 때만.
- 사진·일러스트에는 흰색 10% 1px 외곽선(`outline-white/10`)을 둔다.
- 퇴장은 등장보다 짧고 작게.

어두운 바탕에서는 그림자가 잘 보이지 않아, 면 구분은 그림자 대신 `line` 테두리를 쓴다.
