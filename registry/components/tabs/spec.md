# 탭 기능 명세
같은 화면 안에서 관련 내용을 나눠 바꿔 보는 탭. 밑줄이 선택을 표시한다.

## 목적
- 한 대상에 속한 내용(상세·리뷰·문의)을 화면 이동 없이 나눠 보여준다.

## 사용자 시나리오
1. 구매자가 상품 화면에서 "리뷰 12"를 눌러 리뷰 내용으로 바꾼다.
2. 키보드 사용자가 →로 "문의"까지 옮기면 내용이 바로 바뀐다.
3. "이벤트" 탭은 비활성이라 누를 수 없고 키보드 이동에서도 건너뛴다.

## 상태
| 상태       | 화면                 | 들어오는 조건 | 나가는 조건    |
|------------|----------------------|---------------|----------------|
| 선택됨     | 진한 글자, 밑줄      | 값 일치       | 다른 탭 선택   |
| 선택 안 됨 | 흐린 글자, 밑줄 없음 | 값 불일치     | 선택           |
| 포커스     | 안쪽 링              | 키보드 포커스 | 포커스 이동    |
| 비활성     | 투명도 40%           | disabled=true | disabled=false |

- 패널은 선택된 탭의 것만 보이고 나머지는 `hidden`이다.

## 동작
- 클릭: 탭을 선택한다. 이미 선택된 탭이면 `onChange`를 호출하지 않는다.
- 키보드: 선택된 탭만 Tab으로 들어간다. ←·→로 이전·다음(처음과 끝은 이어짐), Home·End로 처음·끝 탭으로 옮긴다. 비활성 탭은 건너뛰고, 옮기면 바로 선택되며 포커스가 따라간다.
- 밑줄은 탭마다 하나씩 두고 0.3초 동안 가로로 늘었다 줄어든다.
- 패널은 모두 렌더링하고 숨기므로 다른 탭에 다녀와도 패널 안 상태가 남는다.
- 패널은 Tab으로 포커스를 받을 수 있다.
- `fitted`면 탭을 같은 폭으로 나눈다. 아니면 라벨 폭만큼 차지한다.
- `value`를 넘기면 제어, 아니면 `defaultValue`(없으면 첫 비활성 아닌 탭)로 시작한다.
- 동작 줄이기에서는 밑줄 전환이 없다.

## 예외
- 비활성 탭: 클릭도 키보드 선택도 안 된다.
- 비활성 탭의 `content`는 `null`이어도 된다.
- 탭 개수와 폭 넘침은 처리하지 않는다. 쓰는 쪽에서 5개 안쪽으로 둔다.
- `defaultValue`·`value`가 비활성 탭이나 없는 값이면 막지 않는다. 쓰는 쪽에서 유효한 값을 넘긴다.
- 패널을 미리 모두 렌더링하므로 무거운 내용의 지연 로딩은 쓰는 쪽에서 처리한다.

## 인수 조건
- Given "상세 정보" 선택, When "리뷰 12"를 클릭한다, Then 리뷰 패널만 보이고 `onChange("review")`가 호출된다.
- Given "문의" 선택에 포커스, When →를 누른다, Then 비활성 "이벤트"를 건너뛰고 "상세 정보"가 선택되며 포커스가 간다.
- Given 입력 중이던 패널, When 다른 탭에 갔다가 돌아온다, Then 입력 내용이 남아 있다.
- Given "이벤트" 탭이 비활성, When 클릭한다, Then 선택이 바뀌지 않는다.
- Given 포커스가 탭 목록 밖, When Tab으로 들어온다, Then 선택된 탭에만 포커스가 간다.
- Given 탭이 선택됨, When 스크린리더로 읽는다, Then 해당 탭이 `aria-selected=true`이고 패널과 `aria-controls`로 연결된다.

## 측정
- `tab_changed` { tabs_id, from, to, input: "pointer" | "keyboard" }
- 탭 안 콘텐츠 반응(예: 리뷰 조회)은 쓰는 쪽 이벤트로 남긴다.

## 범위 밖
- 주소(URL)와 탭 선택 동기화.
- 탭 내용 비동기 로딩과 빈 상태 화면.
- 탭 추가·삭제·순서 변경, 가로 스크롤.
- 세로 탭.
