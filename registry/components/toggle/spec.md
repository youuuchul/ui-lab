# 토글 기능 명세
설정을 켜거나 끄는 두 상태 입력. 누르는 즉시 적용된다.

## 목적
- 알림처럼 누르는 즉시 적용되는 설정의 켜짐·꺼짐을 한눈에 보여준다.
- 상위·하위 설정이 연동될 때 사용자가 고른 값이 사라지지 않게 한다.

## 사용자 시나리오
1. 사용자가 "푸시 알림"을 끄면 하위 "댓글·답글"과 "야간 알림"이 꺼진 모양으로 바뀐다.
2. 푸시를 다시 켜면 사용자가 고른 하위 값이 돌아온다.
3. 푸시가 꺼진 채 "야간 알림"을 켜면 푸시와 야간 알림만 켜지고, 다른 하위는 켜지지 않는다.

## 상태
| 상태   | 화면                         | 들어오는 조건 | 나가는 조건      |
|--------|------------------------------|---------------|------------------|
| 켬     | 포인트색 바탕, 손잡이 오른쪽 | checked=true  | 클릭·Space·Enter |
| 끔     | 옅은 바탕, 손잡이 왼쪽       | checked=false | 클릭·Space·Enter |
| 비활성 | 투명도 50%                   | disabled=true | disabled=false   |
| 포커스 | 바깥 링                      | 키보드 포커스 | 포커스 이동      |

- 상위·하위 연동은 쓰는 쪽 로직이다. 데모는 하위 값을 따로 기억하고 화면에 `상위 && 하위`로 보인다.

## 동작
- 클릭·Space·Enter: 값을 뒤집고 `onChange(바뀐 값)`을 호출한다.
- `checked`를 넘기면 제어 모드, 안 넘기면 `defaultChecked`(기본 꺼짐)로 시작하는 내부 상태를 쓴다.
- 접근성 이름은 `label`, 설명은 `description`이다. `hideLabel`이면 화면에서만 숨긴다.
- 스위치 위아래로 투명 영역을 넓혀 터치 영역을 확보한다.
- 상위를 끄면 하위는 꺼진 모양이 되고 저장된 하위 값은 유지된다.
- 상위가 꺼진 채 하위를 켜면 상위와 그 항목만 켜고, 다른 하위는 모두 끈 채로 둔다.
- 동작 줄이기에서는 손잡이 이동과 색 전환이 없다.

## 예외
- 비활성: 클릭해도 `onChange`가 호출되지 않는다.
- 제어 모드에서 `checked`를 갱신하지 않으면 화면이 바뀌지 않는다.
- 저장 실패: 컴포넌트는 알지 못한다. 쓰는 쪽에서 낙관적으로 바꾸고 실패 시 이전 값으로 되돌린다.
- 연속 클릭: 누를 때마다 `onChange`가 호출된다. 서버 요청 합치기는 쓰는 쪽에서 처리한다.

## 인수 조건
- Given 푸시 켬·야간 알림 켬, When 푸시를 끈다, Then 야간 알림이 꺼진 모양으로 보인다.
- Given 위 상태에서 푸시를 껐음, When 푸시를 다시 켠다, Then 야간 알림이 켜진 모양으로 돌아온다.
- Given 푸시 끔, When 야간 알림을 켠다, Then 푸시와 야간 알림만 켜지고 댓글·답글은 꺼져 있다.
- Given 토글에 포커스, When Space를 누른다, Then 값이 바뀌고 `aria-checked`가 따라 바뀐다.
- Given `disabled=true`, When 클릭한다, Then `onChange`가 호출되지 않는다.
- Given `defaultChecked`만 넘긴 토글, When 클릭한다, Then 부모 상태 없이 화면이 바뀐다.

## 측정
- `setting_toggled` { setting_key, value, source: "parent" | "child" }
- `setting_save_failed` { setting_key, reason } : 저장 실패로 되돌릴 때

## 범위 밖
- 서버 저장, 실패 시 되돌리기, 기기 권한 요청.
- 상위·하위 연동 규칙의 구현(예시 코드는 README).
- 제출로 확정하는 값(약관 동의 등)에는 쓰지 않는다. 체크박스를 쓴다.
