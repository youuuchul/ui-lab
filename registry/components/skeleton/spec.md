# 스켈레톤 기능 명세
내용이 오기 전 자리를 미리 잡아 두는 회색 틀. 로딩이 끝나도 화면이 튀지 않는다.

## 목적
- 내용이 오기 전에 들어갈 자리를 같은 크기로 잡아 두어, 로딩이 끝날 때 레이아웃이 움직이지 않게 한다.

## 사용자 시나리오
1. 사용자가 구성원 카드를 열면 원형 아바타, 이름·직함 줄, 메모 상자가 회색 틀로 먼저 보인다.
2. 내용이 오면 같은 크기의 실제 아바타·이름·메모로 바뀌고 아래 요소가 밀리지 않는다.

## 상태
| 상태        | 화면            | 들어오는 조건  | 나가는 조건    |
|-------------|-----------------|----------------|----------------|
| 로딩        | 회색 틀, 깜빡임 | 쓰는 쪽이 렌더 | 쓰는 쪽이 제거 |
| 동작 줄이기 | 회색 틀, 정지   | 시스템 설정    | 설정 해제      |

- 스켈레톤은 상태를 갖지 않는다. 로딩이 끝나면 쓰는 쪽이 스켈레톤을 실제 내용으로 바꾼다.
- 모양은 `rect`(둥근 상자)·`circle`(원)·`text`(글줄)이다.

## 동작
- 입력에 반응하지 않는다. 포커스도 받지 않는다.
- 크기는 `className`(예: `h-10 w-10`)으로 정한다. `rect`·`circle`에 크기를 주지 않으면 높이가 없다.
- `text`는 높이 12px 줄을 `lines`개 그린다. 줄이 둘 이상이면 마지막 줄이 폭의 60%다.
- 회색 틀은 천천히 깜빡인다. `prefers-reduced-motion`이면 정지한다.
- 틀은 `aria-hidden`이라 스크린리더가 읽지 않는다. 로딩 알림은 감싸는 영역의 `aria-busy`로 한다(데모 기준).
- 상태가 없어 서버 컴포넌트에서도 쓴다.

## 예외
- 0.3초 안에 끝나는 요청: 컴포넌트가 지연 표시를 하지 않아 깜빡임만 생긴다. 쓰는 쪽에서 표시 시점을 늦춘다.
- 로딩 실패·빈 결과: 처리하지 않는다. 쓰는 쪽에서 오류·빈 화면으로 바꾼다.
- `lines`가 1이면 한 줄이 전체 폭이다. 0 이하이면 아무것도 그리지 않는다.
- 실제 내용과 크기가 다르면 전환 때 화면이 움직인다. 크기 맞추기는 쓰는 쪽에서 한다.
- 버튼·입력칸처럼 바로 쓸 수 있는 요소는 가리지 않는다. 쓰는 쪽에서 판단한다.

## 인수 조건
- Given `shape="circle"`·`className="h-10 w-10"`, When 렌더한다, Then 40px 회색 원이 보인다.
- Given `shape="text"`·`lines={3}`, When 렌더한다, Then 세 줄이 보이고 마지막 줄만 폭 60%다.
- Given 로딩 중인 영역에 `aria-busy=true`, When 스크린리더로 읽는다, Then 스켈레톤 틀은 읽히지 않고 영역이 진행 중으로 알려진다.
- Given 로딩 상태와 내용 상태의 높이가 같음, When 로딩이 끝나 내용으로 바뀐다, Then 아래 요소의 위치가 변하지 않는다.
- Given 동작 줄이기 설정, When 스켈레톤을 본다, Then 깜빡이지 않는다.
- Given 스켈레톤 위, When Tab을 누른다, Then 포커스가 가지 않는다.

## 측정
- `content_load_completed` { screen, skeleton_shown, duration_bucket } : 쓰는 쪽에서 로딩 완료 시 남긴다.
- `content_load_failed` { screen, reason }

## 범위 밖
- 로딩 상태 관리, 표시 지연, 최소 표시 시간.
- 실패·빈 결과 화면.
- 실제 레이아웃에 맞춘 틀의 조립(카드·목록 단위).
- 진행률 표시.
