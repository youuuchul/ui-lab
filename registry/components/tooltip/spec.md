# 툴팁 기능 명세
아이콘 버튼에 마우스를 올리거나 포커스하면 이름과 단축키를 짧게 보여주는 말풍선.

## 목적
- 글자 없는 아이콘 버튼이 무슨 기능인지, 단축키가 무엇인지 사용 중에 확인하게 한다.

## 사용자 시나리오
1. 편집기 도구 막대에서 마우스를 "굵게" 아이콘에 올리면 잠시 뒤 "굵게 ⌘B"가 위에 뜬다.
2. 키보드 사용자가 Tab으로 "링크 넣기"에 오면 바로 "링크 넣기 ⌘K"가 보이고, Esc로 닫는다.

## 상태
| 상태 | 화면                  | 들어오는 조건           | 나가는 조건        |
|------|-----------------------|-------------------------|--------------------|
| 닫힘 | 보이지 않음(DOM 유지) | 초기                    | 호버·키보드 포커스 |
| 대기 | 보이지 않음           | 마우스 올림             | 300ms 경과·벗어남  |
| 열림 | 트리거 위/아래 말풍선 | 대기 종료·키보드 포커스 | 벗어남·blur·Esc    |

- 마우스 호버만 `delay`(기본 300ms) 뒤 열린다. 키보드 포커스는 바로 열린다.

## 동작
- 마우스 올림: `delay` 뒤 열린다. 기다리는 중에 벗어나면 열리지 않는다.
- 마우스 벗어남·포커스 해제: 즉시 닫힌다.
- 키보드 포커스(`:focus-visible`): 즉시 열린다. 마우스 클릭으로 생긴 포커스는 열지 않는다.
- Esc: 열려 있으면 닫는다.
- 터치·펜 등 마우스가 아닌 포인터로는 열지 않는다.
- 말풍선은 `role="tooltip"`이고 트리거에 `aria-describedby`로 연결된다. 아이콘 버튼의 이름은 쓰는 쪽이 `aria-label`로 준다.
- `side`로 위(기본)·아래를 정한다. 열리면 0.15초 동안 페이드하며 4px 이동한다. 동작 줄이기에서는 전환이 없다.
- 말풍선은 포인터를 받지 않는다. 최대 너비 14rem이다.

## 예외
- 화면 가장자리 충돌: 뒤집거나 밀지 않아 잘릴 수 있다. 쓰는 쪽에서 여백을 두거나 위치 계산 도구를 쓴다.
- 터치 기기: 보이지 않는다. 꼭 필요한 정보를 툴팁에만 두지 않는다.
- 트리거가 포커스를 못 받는 요소이면 키보드로 열지 못한다. 쓰는 쪽에서 `button` 등을 쓴다.
- `children`은 요소 하나만 받는다. 여러 개를 넘기지 않는다.
- 말풍선 안에는 링크·버튼을 넣을 수 없다. `content`는 문자열이다.
- 비활성 버튼에서는 이벤트가 오지 않아 열리지 않을 수 있다. 쓰는 쪽에서 확인한다.

## 인수 조건
- Given 마우스 사용, When "굵게" 아이콘에 올리고 300ms를 기다린다, Then "굵게 ⌘B"가 보인다.
- Given 마우스 사용, When 올린 뒤 300ms 안에 벗어난다, Then 말풍선이 나타나지 않는다.
- Given 키보드 사용, When Tab으로 아이콘에 포커스한다, Then 지연 없이 말풍선이 보인다.
- Given 말풍선이 열림, When Esc를 누른다, Then 닫히고 포커스는 버튼에 남는다.
- Given 터치 기기, When 아이콘을 탭한다, Then 말풍선이 열리지 않는다.
- Given 닫힌 상태, When 스크린리더로 트리거를 읽는다, Then `aria-describedby`가 존재하는 툴팁 요소를 가리킨다.

## 측정
- `tooltip_opened` { target_id, input: "hover" | "focus" } : 열림 횟수가 많으면 아이콘 의미가 불명확하다는 신호로 본다.
- 기능 사용은 툴팁이 아닌 버튼 이벤트(예: `toolbar_action_used` { action, source })로 남긴다.

## 범위 밖
- 터치 기기용 안내 방식.
- 화면 경계 계산, 자동 위치 뒤집기.
- 링크·버튼이 든 팝오버, 긴 설명.
- 아이콘 버튼의 접근성 이름(`aria-label`).
