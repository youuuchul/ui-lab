# 3D 역량 그래프 히어로 기획 문서
프로젝트와 역량을 3D 그래프로 잇는 첫 화면.

## PRD 요약
### 문제
- PDF 포트폴리오는 페이지 단위라 프로젝트와 역량의 관계가 한눈에 보이지 않는다. 웹 버전은 스크롤 흐름과 애니메이션으로 차별화한다. (포트폴리오 사이트 저장소/HANDOFF.md 목표 1)
- 방문자는 채용 담당자, GitHub 방문자, 외주 의뢰인 세 부류다. 첫 화면에서 무엇을 하는 사람인지 짧은 시간에 알아야 한다. (HANDOFF.md 목표 2, 가정: 첫 화면 체류가 짧다)

### 대상 사용자
- 포트폴리오 첫 화면에 들어온 채용 담당자·의뢰인
- 개인 작업물 사이트의 첫 화면을 만드는 사람

### 목표 지표
- 출처 문서에 정의된 지표가 없다. 아래는 모두 (가정).
- 첫 화면 통과율: 첫 화면 아래 섹션까지 스크롤한 방문 수 / 방문 수
- 노드 탐색률: 노드에 한 번 이상 올리거나 끈 방문 수 / 방문 수

### 해결 방향
- 프로젝트·역량·영역을 노드로, 쓰임을 선으로 잇는 3D 힘 그래프를 첫 화면 배경에 깐다.
- 제목은 그래프 위에 겹치고, 포인터는 그래프로 통과시킨다.
- 천천히 돌다가 노드에 올리면 멈추고 이웃만 남긴다.

### 범위
- 담은 것: 진입 연출 2종, 자동 회전, 호버 강조, 끌어서 회전, 시차, 라벨 겹침 정리, 스크린리더용 목록
- 뺀 것과 이유 (블록 README 기준): 첫 화면에 필요한 진입·회전·호버만 남김
  - 노드 모양(결정체·팔면체)
  - 필터·고정·노드 카드
  - 조이스틱 회전, 핀치 줌
  - 스크롤 연동
  - 라벨 4방향 배치

### 위험과 확인할 것
- 선에 타입과 근거가 없으면 "이 선은 무슨 뜻인가"에 그래프만으로 답할 수 없다. 분류 선과 증거 선이 같은 모양이다. (포트폴리오 사이트 저장소/docs/graph-data-review.md)
- 노드 크기를 연결 수로 정하면 비중이 큰 항목이 작게 보일 수 있다. (같은 문서)
- 라벨 겹침 점검이 무작위 배치에서 가끔 실패한다. (포트폴리오 사이트 저장소/docs/backlog.md 알려진 한계)
- 저사양 기기에서 프레임이 떨어질 수 있다. 화면 밖·할 일 없음에서는 그리기를 쉰다.

## 단계 분리
| 단계 | 범위                   | 확인할 것         |
|------|------------------------|-------------------|
| MVP  | 진입·회전·호버         | 첫 화면 통과율    |
| v1   | 노드 카드, 필터·고정   | 노드 탐색률       |
| v2   | 조이스틱 회전, 핀치 줌 | 휴대폰 조작 손맛  |
| v3   | 선 타입·근거 연결      | 선 의미 설명 가능 |

## 유저 스토리
- 처음 온 방문자로서, 이 사람이 무엇을 해 왔는지 보기 위해 프로젝트와 역량의 연결을 한 화면에서 보고 싶다.
  - Given `entry="settle"`, When 첫 화면이 열린다, Then 자리 잡힌 배치에서 노드가 `order` 순서로 떠오른다.
  - Given 진입이 끝남, When 아무 조작이 없다, Then 그래프가 천천히 돈다.
- 관심이 생긴 방문자로서, 한 프로젝트에 쓰인 역량만 보기 위해 노드에 올려 보고 싶다.
  - Given 회전 중, When 프로젝트 노드에 올린다, Then 회전이 멈추고 이웃만 남기고 나머지는 흐려진다.
  - Given 노드에서 벗어남, When 1.2초가 지난다, Then 다시 돈다.
- 스크린리더 사용자로서, 그래프 내용을 알기 위해 노드와 연결을 목록으로 듣고 싶다.
  - Given `label` 없음, When 그래프 영역에 닿는다, Then 노드 수·연결 수·주요 노드 이름을 읽는다.

## 기능 명세
### 상태
| 상태      | 화면                   | 들어오는 조건          | 나가는 조건     |
|-----------|------------------------|------------------------|-----------------|
| 진입      | 노드가 떠오름/퍼짐     | 마운트, 글꼴 로드      | 연출 끝         |
| 자동 회전 | 천천히 돎              | 진입 끝, 조작 끝 1.2초 | 노드 호버, 끌기 |
| 호버      | 이웃만 남김, 회전 멈춤 | 노드에 올림            | 노드에서 벗어남 |
| 끌기      | 손으로 회전            | 끌기 시작              | 놓음            |
| 쉼        | 그리기 멈춤            | 화면 밖, 할 일 없음    | 화면 안, 조작   |

### 동작
- `settle`: 배치를 미리 300틱 계산하고, 노드당 20ms 간격으로 제자리에서 떠오른다. `timelapse`: 12단계로 이웃 근처에서 생기며 퍼지고 끝나면 화면에 맞춰 확대된다.
- 자동 회전은 약 1.5초에 걸쳐 출발하고, 노드에 올리면 약 0.4초에 멈춘다.
- 호버: 이웃 외 노드는 20%로 흐리고 연결선은 그 노드 색으로 강조한다.
- 마우스 위치로 살짝 기울고, 끌면 돈다. 깊이에 따라 뒤쪽은 흐리다.
- 라벨은 노드 아래. 겹치면 호버·이웃 > `big` > 연결 수 순으로 남긴다.

### 예외
- 동작 줄이기: 최종 배치를 바로 그리고 돌지 않는다.
- 글꼴 로딩 실패: 기다리지 않고 진입 연출을 시작한다.
- 작은 노드 라벨: 화면에서 작아지면 숨긴다.
- `color`는 `#rrggbb`만 받는다. 다른 형식: 쓰는 쪽에서 처리.
- `data`가 바뀌면 그래프를 새로 만든다. 렌더마다 새 객체를 넘기지 않게 고정하는 것은 쓰는 쪽에서 처리.
- 빈 데이터, 노드 클릭 후 이동: 쓰는 쪽에서 처리.

### 측정
- 출처 문서에 이벤트 정의가 없다. 이름은 모두 (가정).
- `hero_graph_node_hovered` { node_id, big }
- `hero_graph_dragged` { duration_ms }
- `hero_scrolled_past` { time_on_hero_ms }
