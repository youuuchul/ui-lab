# 견적 안내 시트 기획 문서
업무 묶음별 범위·결과물·기간과 진행 순서를 정리한 안내 페이지.

## PRD 요약
### 문제
- 외주 의뢰인은 무엇을 맡길 수 있고 무엇을 받는지, 얼마나 걸리는지를 문의 전에 알고 싶다. (웹 포트폴리오 저장소/docs/copy-proposals.md 2, 가정: 문의 전 확인 수요)
- 의뢰 메일마다 같은 범위·기간 설명을 반복해서 답한다. 견적 페이지 링크로 한 번에 답한다. (웹 포트폴리오 저장소/docs/quote-page.md)
- 메인 사이트에는 범위·기간만 싣고 가격은 따로 둔다. (quote-page.md, copy-proposals.md 결정 항목)

### 대상 사용자
- 의뢰 메일을 보낸 뒤 회신 링크로 들어온 외주 의뢰인 (HANDOFF.md 목표 2)
- 업무 범위를 한 장으로 안내하려는 프리랜서·작은 스튜디오

### 목표 지표
- 출처 문서에 정의된 지표가 없다. 아래는 모두 (가정).
- 문의 전환율: 하단 문의 링크 클릭 수 / 시트 열람 수
- 회신 후 재문의율: 시트 링크를 받은 의뢰 중 다시 답장한 비율. 의뢰 메일은 제목 머리말로 구분한다. (copy-proposals.md 3)

### 해결 방향
- 업무를 묶음으로 나누고 한 줄에 설명·결과물·기간을 둔다.
- 표 아래에 참고 사항, 그 아래에 진행 순서 카드를 둔다.
- 마지막에 문의 버튼 자리를 둔다.

### 범위
- 담은 것: 업무 묶음과 줄, 결과물·숫자 칸 라벨 변경, 참고 사항, 진행 순서, 하단 링크, 제목 수준 조절, 좁은 화면 배치
- 뺀 것: 블록 README에 목록이 없다. 원본 문서 기준 블록 밖에 둔 것 (quote-page.md)
  - 시작가 데이터 분리: 가격 노출 여부는 쓰는 쪽 결정. 숫자 칸은 `value` 문자열로 받음
  - 비공개 주소·검색 제외 설정: 배포 영역
  - 의뢰 메일 자동 회신: 메일 계정 쪽 스크립트 영역

### 위험과 확인할 것
- 기간·가격을 확정값처럼 읽을 수 있다. 원본도 기간 제안값의 확정 여부가 결정 대기다. (웹 포트폴리오 저장소/docs/backlog.md)
- 가격을 숫자 칸에 넣으면 공개 페이지에 그대로 노출된다. 공개 범위를 먼저 정한다.
- 줄 수가 많으면 한 장이 길어진다. 묶음 수를 줄인다.

## 단계 분리
| 단계 | 범위                     | 확인할 것          |
|------|--------------------------|--------------------|
| MVP  | 업무·결과물·기간 시트    | 문의 전환율        |
| v1   | 비공개 주소, 시작가 추가 | 메인에 가격 미노출 |
| v2   | 의뢰 메일 자동 회신 연결 | 회신 1회만 발송    |

## 유저 스토리
- 외주 의뢰인으로서, 맡길지 판단하기 위해 업무별 범위·결과물·기간을 한 장에서 보고 싶다.
  - Given 묶음 2개·줄 3개, When 시트를 연다, Then 묶음 제목 아래 줄마다 설명·결과물·기간이 보인다.
  - Given 폭 36rem 미만 컨테이너, When 시트를 연다, Then 결과물이 아래 줄로 내려가고 기간은 오른쪽 위에 남는다.
- 진행 방식이 궁금한 의뢰인으로서, 문의 뒤 무슨 일이 일어나는지 알기 위해 진행 순서를 보고 싶다.
  - Given `steps` 4개, When 시트를 본다, Then 번호가 붙은 카드 4개가 한 줄에 나눠 앉는다.
  - Given `steps` 없음, When 시트를 본다, Then 진행 순서 영역이 없다.
- 시트를 페이지에 넣는 사람으로서, 문서 구조를 맞추기 위해 제목 수준을 바꾸고 싶다.
  - Given 페이지에 이미 h1이 있음, When `headingLevel={2}`, Then 제목은 h2, 묶음 제목은 h3, 줄 제목은 h4가 된다.

## 기능 명세
### 상태
| 상태      | 화면                    | 들어오는 조건       | 나가는 조건 |
|-----------|-------------------------|---------------------|-------------|
| 넓은 배치 | 설명·결과물·숫자 3칸    | 컨테이너 36rem 이상 | 폭 줄어듦   |
| 좁은 배치 | 결과물 아래 줄, 숫자 위 | 컨테이너 36rem 미만 | 폭 늘어남   |

- 사용자 조작 상태는 없다. 서버 컴포넌트로도 쓸 수 있다.

### 동작
- 숫자 칸 라벨은 `valueLabel`(기본 "기간"), 결과물 라벨은 `outputLabel`(기본 "결과물").
- 진행 순서 카드는 `auto-fit`으로 개수만큼 한 줄에 나눈다. 번호는 자동.
- 하단 `footer`는 넘긴 그대로 그린다.

### 예외
- `kicker`·`sub` 없음: 그 줄을 생략한다.
- `notes`·`steps`가 없거나 빈 배열: 그 영역을 생략한다.
- `footer` 없음: 하단 영역을 생략한다.
- 가격 노출 여부, 문의 링크 주소, 메일 제목 머리말: 쓰는 쪽에서 처리.
- 빈 `groups`, 줄 정렬 순서: 쓰는 쪽에서 처리.

### 측정
- 출처 문서에 이벤트 정의가 없다. 이름은 모두 (가정).
- `quote_viewed` { source: "mail_reply" | "direct" }
- `quote_cta_clicked` { target }
- 메일 문의는 제목 머리말로 분류한다. (copy-proposals.md 3, 폼 서비스 대신 메일 제목 접두어)
