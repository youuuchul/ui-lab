# KPI 개요 대시보드 기획 문서
기간을 바꾸면 핵심 지표 스코어보드와 북극성 지표 추이·분해 타일이 함께 바뀌는 개요 화면.

## PRD 요약
### 문제
- 경영진·전 직군이 "서비스가 이번 기간 커지고 있는가"를 한 화면에서 답해야 한다. (PlaceWave 저장소/docs/metrics.md 탭이 답하는 질문 · 개요)
- 플랫폼 매출은 수수료보다 월 구독료 비중이 커서 매출만 보면 거래 변화가 늦게 보인다. 거래 단위인 결제 건수를 앞에 둔다. (PlaceWave 저장소/README.md 북극성 지표)
- 거래액은 가격을 타서 결제 건수와 따로 움직인다. 결제·객단가·거래액을 나란히 둬야 원인이 갈린다. (같은 문서)

### 대상 사용자
- 주간 회의 전에 기간 성과를 훑는 경영진·PM
- 증감 원인을 다른 탭으로 좇기 전에 출발점을 잡는 분석가

### 목표 지표
- 북극성: 티켓 결제 건수(C12 결제, 환불 포함). (metrics.md 북극성 지표)
- 입력 지표: 전체 전환율, 결제자, 객단가. 가드레일: 환불률 10% 안쪽, 실효 수수료율 5~7%. (같은 문서)
- 이 화면 자체의 성공 기준: 기간 전환 후 다른 탭으로 이동하는 비율 (가정, 원본에 화면 이벤트 계측 없음)

### 해결 방향
- 맨 위 기간 선택 → 기준일 현황(필터 무관) → 핵심 지표 6칸 → 북극성 추이 카드.
- 추이 카드는 결제 실선, 신청 보조선, 전기 결제 점선을 겹치고 오른쪽에 결제·객단가·거래액 타일을 둔다. (PlaceWave 저장소/docs/dashboard.md §3b)

### 범위
- 담은 것: 기간 전환(7·28·90일), 스코어보드 6칸, 결제 추이 카드와 분해 타일, 기준일 현황
- 뺀 것과 이유
  - 채널·플랫폼·회원 필터: 사람 지표의 기간 고유 집계가 필요해 데모 데이터로 재현하지 않음
  - 방문자·가입·활성 구독자·파트너 공간·매출 구성 추이 카드: 같은 부품의 반복이라 결제 카드 하나로 대표
  - 입자 토글(자동·일·주·월), 차트 클릭 드릴다운, URL 상태 저장: 화면 상태 관리 영역

### 위험과 확인할 것
- 기간별 값은 미리 계산된 묶음이라, 실제 서비스에서는 기간마다 집계 비용이 든다.
- 방문자처럼 사람 지표를 일별 값 합으로 만들면 사람·일이 되어 부풀려진다. (dashboard.md §1 원칙 5)
- 90일 결제 ▲ 81.0%처럼 큰 증감은 직전 기간(3/25~6/22) 규모에 좌우된다. 비교 기준을 소제목과 추이 카드 머리에 함께 적는다.

## 단계 분리
| 단계 | 범위                                  | 확인할 것                              |
|------|---------------------------------------|----------------------------------------|
| MVP  | 기간 전환, 스코어보드, 결제 추이 카드 | 기간을 바꿀 때 모든 값이 함께 바뀌는가 |
| v1   | 나머지 추이 카드 5개, 입자 토글       | 스코어보드와 카드 순서 1:1             |
| v2   | 세그먼트 필터, 세그먼트 분해 타일     | 필터 시 축 없는 카드 숨김              |
| v3   | 차트 드릴다운, URL 상태               | 링크 공유 시 같은 화면                 |

## 유저 스토리
- 주간 회의를 준비하는 PM으로서, 이번 기간이 직전보다 나아졌는지 알기 위해 핵심 지표를 한 줄로 보고 싶다.
  - Given 28일 선택, When 화면을 연다, Then 소제목 "핵심 지표 · 직전 28일 대비"와 결제 6,314건 ▲ 9.0%가 첫 칸에 보인다.
  - Given 가입 ▼ 16.0%, When 렌더한다, Then 화살표와 빨간색으로 나빠졌음이 보인다.
- 기간을 바꿔 보는 경영진으로서, 길게 보면 어떤지 확인하기 위해 기간을 90일로 바꾸고 싶다.
  - Given 28일, When 90일을 누른다, Then 스코어보드·추이(주별 13구간)·분해 타일·기간 표시가 함께 바뀐다.
  - Given 기간 선택에 포커스, When → 를 누른다, Then 다음 기간이 선택된다.
- 결제 증감의 원인을 찾는 분석가로서, 건수와 가격 효과를 가르기 위해 결제·객단가·거래액을 함께 보고 싶다.
  - Given 90일, When 분해 타일을 본다, Then 결제 ▲ 81.0%, 객단가 ▼ 3.1%, 거래액 ▲ 74.3%가 나란히 보인다.
  - Given 추이 차트 포커스, When → 로 구간을 옮긴다, Then 그 주의 결제·신청·전기 결제가 툴팁과 읽기 문장으로 나온다.

## 기능 명세
### 상태
| 상태      | 화면                                       | 들어오는 조건     | 나가는 조건          |
|-----------|--------------------------------------------|-------------------|----------------------|
| 기간 표시 | 선택 기간의 스코어보드·추이·타일·기간 문구 | 마운트, 기간 선택 | 다른 기간 선택       |
| 구간 확인 | 추이 카드 세로선·툴팁                      | 포인터, 화살표    | 이탈, Esc, 기간 전환 |

### 동작
- 기간 선택은 40px 높이 라디오 그룹(세그먼트 컨트롤)이다. 화살표로 옮기면 바로 바뀐다.
- 입자: 14일 이하 일별, 그 이상 기간 시작일부터 7일씩 주별(마지막 주는 짧을 수 있음). (dashboard.md §3b)
- 전기: 직전 같은 길이 기간의 같은 위치 구간을 점선으로 겹친다. (같은 문서)
- 증감: 직전 동일 길이 기간 대비, 건수·금액 %. (dashboard.md §3 증감)
- 활성 구독자·파트너 공간은 잔액형이라 보조 줄에 기준일("9/20 기준")을 적는다.

### 예외
- 직전 기간이 데이터 범위 밖: 증감 줄을 비우고 추이에서 점선을 뺀다. 데모 기간은 모두 범위 안이다.
- 값이 없는 구간: 선을 끊는다(0으로 채우지 않음).
- 데이터 로딩·오류: 쓰는 쪽에서 처리한다.

### 측정
- `overview_period_changed` { from, to } (가정): 기간 전환.
- `trend_point_inspected` { chart: "payment", bucket, input } (가정): 구간 확인, 세션당 첫 1회.
- 원본 저장소는 대시보드 사용 이벤트를 남기지 않는다. 위 이벤트는 이 적용 사례에서 제안하는 것이다.
