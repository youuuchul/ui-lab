# 3D 폰 목업 기획 문서
코드로 만든 3D 폰에 화면을 띄우고 포인터에 따라 기울이는 목업.

## PRD 요약
### 문제
- 웹 포트폴리오는 PDF와 달리 실제 앱 화면을 보여줄 수 있어야 한다. (웹 포트폴리오 저장소/HANDOFF.md 목표 1)
- 평면 캡처만으로는 휴대폰 앱이라는 맥락이 약하다. (가정)
- WebGL을 못 쓰는 환경에서도 화면은 보여야 한다. (웹 포트폴리오 저장소/docs/phone-3d.md)

### 대상 사용자
- 서비스 기획·구현 사례를 보는 방문자
- 앱 화면을 소개 페이지에 싣는 사람

### 목표 지표
- 출처 문서에 정의된 지표가 없다. 아래는 모두 (가정).
- 대체 화면 비율: 대체(CSS) 폰으로 보인 수 / 목업 노출 수
- 기울기 허용률: 기울기 권한 허용 수 / 권한 요청 수

### 해결 방향
- three.js로 폰을 코드에서 만들고, 화면 이미지를 원색 그대로 띄운다.
- 마우스는 포인터 쪽으로, 휴대폰은 기울기를 따라 돈다.
- WebGL 준비 전·실패 시 CSS 3D 폰을 보여준다.

### 범위
- 담은 것: 코드 폰 한 대, 포인터·기울기 반응, iOS 권한 요청, CSS 대체 폰, three.js 지연 로딩
- 뺀 것과 이유 (블록 README 기준)
  - GLB 모델 로더와 설정 파일: 코드 폰만으로 목업이 되므로. 모델을 바꾸려면 기본 폰 생성부를 GLTFLoader 결과로 교체
- 블록에 없는 원본 기능 (웹 포트폴리오 저장소/docs/phone-3d.md): 모델 보정 화면, 원형 캐러셀에 여러 대 배치

### 위험과 확인할 것
- three.js 청크가 크다. 화면 가까이에서만 불러오는지 확인한다. (phone-3d.md)
- iOS 기울기 권한 창은 실기기에서만 확인된다. (웹 포트폴리오 저장소/docs/backlog.md 실기기 확인)
- 화면 이미지 비율이 폰 화면과 다르면 잘린다. 390×844 비율 캡처를 권장한다. (phone-3d.md)

## 유저 스토리
- 데스크톱 방문자로서, 앱이 실제로 어떻게 보이는지 느끼기 위해 폰을 마우스로 기울여 보고 싶다.
  - Given WebGL 준비 끝, When 마우스를 폰 오른쪽 위로 옮긴다, Then 폰이 그쪽으로 천천히 돈다.
  - Given 기울어진 상태, When 마우스가 영역을 벗어난다, Then 기본 자세로 돌아온다.
- 휴대폰 방문자로서, 같은 경험을 하기 위해 기기를 기울여 폰을 돌리고 싶다.
  - Given iOS, When 목업을 탭한다, Then 기울기 권한을 묻는다.
  - Given 권한 거부, When 다시 탭한다, Then 다시 묻지 않는다.
- WebGL이 막힌 환경의 방문자로서, 화면 내용을 보기 위해 대체 목업을 보고 싶다.
  - Given WebGL 생성 실패, When 목업 자리를 본다, Then `fallback`의 CSS 폰이 그대로 보인다.

## 기능 명세
### 상태
| 상태        | 화면                  | 들어오는 조건   | 나가는 조건    |
|-------------|-----------------------|-----------------|----------------|
| 준비 중     | `fallback` 표시       | 마운트          | 무대 생성 완료 |
| 포인터 반응 | WebGL 폰, 마우스 따라 | 준비 완료       | 기울기 켜짐    |
| 기울기 반응 | 기기 각도 따라        | 권한 허용·탭    | 없음           |
| 실패        | `fallback` 유지       | 모듈·WebGL 실패 | 없음           |

### 동작
- 자세: 기본은 살짝 비튼 각도. 입력(-1~1)에 따라 좌우·위아래로 돈다.
- 입력은 매 프레임 목표값을 부드럽게 따라간다.
- 기울기는 처음 쥔 각도를 기준점으로 잡고, 기준점이 천천히 따라와 다시 가운데로 돌아온다.
- 권한 요청은 `click` 안에서 한다.
- 컨테이너 크기가 바뀌면 캔버스를 다시 맞춘다.

### 예외
- WebGL·모듈 로딩 실패: `fallback`을 계속 보여준다.
- iOS 권한 거부·오류: 다시 묻지 않고 마우스 반응만 둔다.
- 터치 포인터 이동: 무시한다(마우스만 반응).
- 동작 줄이기: 기울기·포인터 반응 없이 기본 자세로 둔다.
- `fallback`을 넘기지 않으면 준비 전·실패 시 빈 영역: 쓰는 쪽에서 처리.
- 화면 이미지 로딩 실패, 이미지 비율 맞춤: 쓰는 쪽에서 처리.

### 측정
- 출처 문서에 이벤트 정의가 없다. 이름은 모두 (가정).
- `mockup_ready` { renderer: "webgl" | "css" }
- `mockup_tilt_permission` { result: "granted" | "denied" }
