# 퍼널 분석 대시보드 기획 문서
전환 스코어보드 → 단계 전환율 추이 → 세그먼트별 퍼널 → 생키 다이어그램 순서로 이탈 지점을 좁혀 가는 화면.

## PRD 요약
### 문제
- 방문한 사람이 결제까지 가는 길에서 어디서 가장 많이 빠지는지 답해야 한다. (PlaceWave 저장소/docs/metrics.md 탭이 답하는 질문 · 퍼널)
- "어느 단계가, 언제부터, 어느 집단에서 나빠졌나"를 한 화면에서 순서대로 좁혀야 한다. (PlaceWave 저장소/README.md 질문에서 출발한 탭)
- 일별 사람 수를 기간으로 더하면 사람·일이 되어 단계 수가 부풀려진다. (PlaceWave 저장소/docs/dashboard.md §1 원칙 5)

### 대상 사용자
- 퍼널 개선 우선순위를 정하는 프로덕트 담당자
- 배포·캠페인 영향을 확인하는 데이터 분석가

### 목표 지표
- 전체 전환율 C15 = n(결제) ÷ n(랜딩). (metrics.md 전환)
- 최대 이탈 단계 C16, 가장 크게 변한 단계 C17, 탐색 도달률 E01. (같은 문서)
- 화면 성공 기준: 생키까지 내려가 노드·띠를 확인한 비율 (가정)

### 해결 방향
- 스코어보드 4칸으로 지점을 찍고, 추이로 시점을, 세그먼트 표로 집단을, 생키로 경로를 본다.
- 단계는 같은 날 누적 조건(랜딩 ⊇ 행사 상세 ⊇ 로그인·가입 ⊇ 신청 화면 ⊇ 결제)의 기간 고유 사람으로 센다. (dashboard.md §3a)

### 범위
- 담은 것: 스코어보드 4칸, 단계 전환율 주별 추이, 세그먼트별 퍼널(채널·플랫폼·회원), 생키 다이어그램 4열
- 뺀 것과 이유
  - 기간·세그먼트 필터: 기간 고유 사람 재계산이 필요해 28일 하나로 고정
  - 오디언스별 퍼널: 오디언스끼리 겹쳐 별도 설명이 필요한 드릴다운이라 뺌
  - 요일×시간대 세션 히트맵: 퍼널 이탈과 직접 연결되지 않는 보조 카드
  - 생키 5번째 화면 열, 띠 클릭 고정: 데모 폭에서 읽기 쉽게 4열로 줄임

### 위험과 확인할 것
- 퍼널은 같은 날 판정이라 며칠에 걸친 구매 여정은 앞 단계에서 끊긴 것처럼 보인다.
- 세그먼트는 사람마다 기간 안 마지막 해당일 값 하나로 귀속한다. 값별 랜딩 합이 전체와 같은지 확인한다. (dashboard.md §3)
- 생키의 이탈 노드는 세션 단위다. 사람 단위 퍼널 수치와 직접 비교하지 않는다.

## 단계 분리
| 단계 | 범위                                | 확인할 것                      |
|------|-------------------------------------|--------------------------------|
| MVP  | 스코어보드, 세그먼트별 퍼널         | 최대 이탈 단계가 맞게 잡히는가 |
| v1   | 단계 전환율 추이                    | 변화 시점과 배포 일정 대조     |
| v2   | 생키 다이어그램                     | 이탈 직전 화면                 |
| v3   | 기간·세그먼트 필터, 오디언스별 퍼널 | 필터 후 값별 랜딩 합 = 전체    |

## 유저 스토리
- 개선 우선순위를 정하는 PM으로서, 가장 큰 이탈 지점을 먼저 알기 위해 스코어보드를 보고 싶다.
  - Given 28일, When 화면을 연다, Then "최대 이탈 단계 로그인·가입", 보조 줄 "행사 상세에서 −70.6%p"가 보인다.
  - Given 최대 이탈 폭이 직전보다 줄었음(▼ 1.5%p), When 렌더한다, Then 초록으로 보인다.
- 집단 차이를 찾는 분석가로서, 이탈이 어느 집단에 몰리는지 보기 위해 세그먼트별 도달률을 비교하고 싶다.
  - Given 세그먼트 표, When 회원·비회원 행을 본다, Then 로그인·가입 열이 97.8%와 2.5%로 숫자와 명도 모두 크게 다르다.
- 경로를 확인하는 기획자로서, 이탈 직전 화면을 알기 위해 생키를 탐색하고 싶다.
  - Given 생키 포커스, When → 로 2번째 화면 열로 간다, Then 같은 이름 노드가 강조되고 다음 화면 상위 3개를 읽는다.
  - Given 띠에 포인터, When 머문다, Then 세션 수와 출발 화면 세션 중 %가 보인다.

## 기능 명세
### 상태
| 상태      | 화면                    | 들어오는 조건  | 나가는 조건            |
|-----------|-------------------------|----------------|------------------------|
| 기본      | 네 구역 모두 표시       | 마운트         | -                      |
| 추이 확인 | 추이 세로선·툴팁        | 포인터, 화살표 | 이탈, Esc              |
| 경로 확인 | 생키 띠·노드 강조, 툴팁 | 포인터, 화살표 | 이탈, 포커스 이탈, Esc |

### 동작
- 스코어보드: 전체 전환율(%p 증감, 보조 "랜딩 N명 중 M명"), 최대 이탈 단계(이탈 폭 증감, 줄면 좋음), 가장 크게 변한 단계(그 단계 직전 대비 전환율), 탐색 도달률. (dashboard.md §3a)
- 단계 전환율 추이: 28일 이상 주별 버킷마다 c(신청 화면) = 신청 화면 ÷ 행사 상세, c(결제) = 결제 ÷ 신청 화면. (같은 문서)
- 세그먼트별 퍼널: 행 = 전체 + 축별 값, 칸 = 랜딩 대비 도달률, 명도 = 열 안 최소~최대. (같은 문서)
- 경로 비중: 링크 세션 ÷ 출발 노드 세션, 링크 세션 ÷ step 1 세션 합. 열마다 상위 화면만 이름을 두고 나머지는 기타. (같은 문서)

### 예외
- 분모 0인 버킷: 선을 끊는다. (dashboard.md §3a)
- 직전 기간이 데이터 범위 밖: "가장 크게 변한 단계"를 비운다. (같은 문서)
- 생키 데이터가 없을 때 "데이터 없음" 표시, 로딩: 쓰는 쪽에서 처리한다.
