# 추리 게임 플레이 화면

단서를 모아 읽고 범인을 지목하는 머더 미스터리 플레이어 화면. Murder Mystery Generator의 플레이 화면에서 세션·실시간 동기화·API를 뺀 조합이다. 캐릭터와 단서 이미지는 프로젝트에서 직접 만든 에셋이다.

## 조합
| 자리                | 컴포넌트                                                   |
|---------------------|------------------------------------------------------------|
| 보유·공개 단서 목록 | [증거 목록 행](#/item/components/evidence-row)             |
| 범인 지목           | [인물 선택 목록](#/item/components/portrait-choice)        |
| 단서 상세           | 블록 안 모달 (닫기 버튼·배경·Esc, 열린 동안 아래는 비활성) |

## 흐름
1. 단서 탭: 보유 단서는 위치·요약까지, 공개 단서는 장소별로 묶어 보여준다.
2. 행을 누르면 문서 비율(4:5) 이미지와 전체 설명이 모달로 열린다.
3. 투표 탭: 한 명을 고르기 전에는 제출 버튼이 잠겨 있고 "한 명을 고르세요"가 보인다.
4. "이 사람으로 제출" 다음에 확인 단계(제출 / 다시 고르기)를 거친다. 제출 후에는 바꿀 수 없고, 완료 화면에 내가 고른 사람을 보여준다.
5. 제출하면 진행 막대로 투표 인원이 차오르고, 전원이 내면 결과가 공개된다.

## 구현 메모
- 원본 다크 테마 값(바탕 `#09090b`, 강조 `#e0525c`, 모서리 6px)을 유지했다. 강조색은 `--color-accent`를 블록 루트에서 바꿔 하위 컴포넌트까지 적용한다.
- 투표 정책 근거: 원본 `src/app/play/[gameId]/[charId]/_components/PlayerView.tsx`는 제출 후 투표 화면을 완료 화면으로 바꿔 변경 UI가 없다(서버 `src/app/api/sessions/[sessionId]/vote/route.ts`의 덮어쓰기는 동률 재투표용).
- 다른 플레이어의 투표 수는 `voteCount`로 받는다. 실제 서비스에서는 실시간 채널 값을 넣는다.
- 원본에서 뺀 것: 단서 양도, 장소 탐색·획득 제한, 고급(질문별) 투표·재투표, AI 플레이어 투표 집계, 결과·엔딩 화면.
