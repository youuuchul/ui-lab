# 추리 게임 플레이 화면 기획 문서
단서를 모아 읽고 범인을 지목하는 머더 미스터리 플레이어 화면.

## PRD 요약
### 문제
- 플레이어는 한 테이블에 모여 각자 휴대폰으로 접속한다. 내 카드는 나만 보고, 다른 사람 카드는 볼 수 없어야 한다. (docs/SPEC.md 9-0)
- 단서는 보유자만 읽는 것(owned)과 발견 뒤 모두가 읽는 것(shared)으로 나뉜다. 두 종류를 섞어 보여주면 무엇을 남에게 말해야 할지 헷갈린다. (docs/MENTAL-MODEL.md 4-3)
- 투표는 각자 비밀로 고른다. (docs/SPEC.md 2-3)
- 원본은 제출 뒤 바꾸는 화면이 없다. 잘못 누르면 되돌릴 수 없다. (가정, 블록 README의 투표 정책 근거)

### 대상 사용자
- 같은 공간에서 머더 미스터리를 하는 플레이어, 휴대폰 화면으로 카드·단서를 본다 (docs/MENTAL-MODEL.md 2)

### 목표 지표
- 출처 문서에 정의된 지표가 없다. 아래는 모두 (가정).
- 투표 완료율: 제출한 플레이어 수 / 세션 참가자 수
- 다시 고르기 비율: 확인 단계에서 다시 고르기를 누른 수 / 확인 단계 진입 수
- 단서 열람률: 상세를 연 단서 수 / 볼 수 있는 단서 수

### 해결 방향
- 단서 탭과 투표 탭 두 개로 나눈다.
- 단서 탭은 보유 단서와 공개 단서를 전환해 보고, 공개 단서는 장소별로 묶는다.
- 투표는 고르기 → 확인 → 완료 세 단계로, 제출 전에 한 번 더 확인한다.

### 범위
- 담은 것: 보유·공개 단서 목록, 단서 상세 모달, 1차 범인 투표, 확인 단계, 투표 진행 막대
- 뺀 것과 이유 (블록 README 기준)
  - 단서 양도: 소유권 이전·실시간 동기화가 필요한 서버 영역
  - 장소 탐색·획득 제한: 조사 회수 차감 등 세션 규칙이 필요
  - 고급(질문별) 투표·재투표: 1차 투표 흐름만 다룸
  - AI 플레이어 투표 집계: 서버 영역. 다른 사람 투표 수는 `voteCount`로 받음
  - 결과·엔딩 화면: 분기 엔딩·개인 엔딩은 별도 화면

### 위험과 확인할 것
- `onVote`가 Promise를 돌려주면 끝날 때까지 "제출 중"으로 버튼을 잠근다. 실패하면 확인 단계에 머물고 "제출하지 못했어요"를 알린다.
- 전원 투표 뒤 결과 공개는 안내 문구만 있다. 실제 공개는 쓰는 쪽 흐름에 달렸다.
- 원본 서버는 동률 재투표를 위해 투표 덮어쓰기를 허용한다. 재투표 화면을 붙일 때 "바꿀 수 없어요" 문구와 맞춘다.

## 단계 분리
| 단계 | 범위                         | 확인할 것        |
|------|------------------------------|------------------|
| MVP  | 단서 목록·상세, 1차 투표     | 투표 완료율      |
| v1   | 장소 탐색, 획득 제한         | 단서 획득 분포   |
| v2   | 단서 건네주기, 실시간 동기화 | 양도 후 열람     |
| v3   | 질문별 투표, 동률 재투표     | 재투표 실동작    |
| v4   | 투표 결과, 분기·개인 엔딩    | 엔딩 끝까지 도달 |

## 유저 스토리
- 단서를 모으는 플레이어로서, 무엇을 공유할지 정하기 위해 내 단서와 공개 단서를 나눠 보고 싶다.
  - Given 보유 단서 3개·공개 단서 2개, When 단서 탭을 연다, Then 보유 단서 (3)과 공개 단서 (2) 전환 버튼이 보인다.
  - Given 공개 단서 보기, When 목록을 본다, Then 장소별로 묶여 장소 이름 옆에 개수가 보인다.
- 추리하는 플레이어로서, 단서를 자세히 읽기 위해 이미지와 전체 설명을 크게 보고 싶다.
  - Given 단서 목록, When 행을 누른다, Then 4:5 이미지와 전체 설명이 모달로 열리고 닫기 버튼에 포커스가 간다.
  - Given 모달 열림, When Esc를 누른다, Then 모달이 닫히고 눌렀던 행으로 포커스가 돌아간다.
- 투표하는 플레이어로서, 실수로 다른 사람을 고르지 않기 위해 제출 전에 한 번 확인하고 싶다.
  - Given 아무도 고르지 않음, When 투표 탭을 연다, Then 제출 버튼이 잠겨 있고 "한 명을 고르세요"가 보인다.
  - Given 한 명을 고름, When "이 사람으로 제출"을 누른다, Then "<이름>님으로 제출할까요?"와 다시 고르기·제출이 보인다.
  - Given 확인 단계, When 제출을 누른다, Then 완료 화면에 내가 고른 사람과 투표 인원이 보인다.

## 기능 명세
### 상태
| 상태      | 화면                        | 들어오는 조건        | 나가는 조건       |
|-----------|-----------------------------|----------------------|-------------------|
| 보유 단서 | 보유 단서 목록              | 첫 진입, 전환        | 공개 단서 전환    |
| 공개 단서 | 장소별 묶음 목록            | 전환                 | 보유 단서 전환    |
| 단서 상세 | 모달, 아래 화면 비활성      | 행 누름              | 닫기, 배경, Esc   |
| 고르기    | 인물 목록, 제출 잠김/열림   | 투표 탭, 다시 고르기 | 제출 버튼         |
| 확인      | 이름 확인, 다시 고르기·제출 | 제출 버튼            | 다시 고르기, 제출 |
| 완료      | 고른 사람, 진행 막대        | 제출                 | 없음              |

### 동작
- 탭 전환은 단서·투표 두 개. 투표 단계는 탭을 오가도 유지된다.
- 보유 단서 행은 제목·위치·요약을, 공개 단서 행은 제목과 "공개 단서"를 보여준다.
- 모달이 열린 동안 아래 화면은 `inert`. 닫으면 열기 전 포커스로 돌아간다.
- 확인 단계에 들어가면 확인 문구로 포커스를 옮긴다.
- 진행 막대: `voteCount / voters` 비율로 차오른다. 고르기·완료 화면 모두 `N / M명 투표 완료`를 보여준다.
- 강조색은 `accent`로 받아 블록 안 하위 컴포넌트까지 바꾼다.

### 예외
- 보유 단서 없음: "보유한 단서가 없습니다". 공개 단서 없음: "아직 공개된 단서가 없습니다".
- 이미지 없는 단서: 모달에 제목·위치·설명만.
- 아무도 고르지 않음: 제출 버튼 잠김.
- 제출 후 변경: 막는다. 완료 화면에 바꾸는 버튼이 없다.
- `voters`가 0: 진행 막대를 0%로 둔다.
- 투표 전송 실패·재시도, 실시간 투표 수 갱신, 전원 투표 뒤 결과 공개: 쓰는 쪽에서 처리.
- 다른 플레이어 단서 접근 권한: 쓰는 쪽(세션 토큰)에서 처리.

### 측정
- 출처 문서에 이벤트 카탈로그가 없다. 이름은 모두 (가정).
- `clue_opened` { clue_id, kind: "owned" | "public", location }: 모달 열 때
- `vote_confirm_shown` { suspect_id }: 확인 단계 진입
- `vote_repicked` { suspect_id }: 다시 고르기
- `vote_submitted` { suspect_id, question }: `onVote`에서
